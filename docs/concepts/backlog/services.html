0. Summary #

  • termiHub has two lists of things that run and listen. SSH tunnels (local, remote, dynamic) are edited in a tab, restart themselves and are shared by all windows. Services (HTTP, FTP, TFTP file servers) are edited in a dialog, have an access log and live in one window. They share a row and nothing else: two activity bar entries, two sets of states, actions, words, confirmations and logs.
  • The maintainer decided (2026-11-25) to merge them into one Services: one sidebar, one New menu, one list, one editor style, one status and log view.
  • Proposal: users pick what they want to do ("Reach something through a server", "Give files to a device"), the technical name stands beside it. A row shows name, state and, while it runs, the address to use. Both kinds get the same states, actions in one order, an editor tab with Settings and Activity, Undo, and a log that answers "why is it down".
  • Stored data stays in its two files. One optional field is added: where a file server runs, which is lost at every restart today (F-1).
  • 14 slices. Slices 1 and 2 fix wrong behavior found while taking stock and are useful even without the merge.

2. Usability today #

  • The question comes second. "I want to reach a database" has to become "SSH tunnel, local" in the user's head before any button fits. "Services" next to "SSH tunnels" does not say that one shares files and the other forwards ports.
  • The result is hidden. The one thing the user needs next, the address, is in a tooltip. Only file servers can copy it, from a right-click menu.
  • Same action, different behavior. Stop asks on one and not on the other. Delete can be undone on one and not on the other. Retry exists on one. Edits are guarded on one.
  • "Why is it down" has no place. A tunnel keeps one last error, shown as a toast. A file server has a log, in a 260 px column inside its own row.
  • Reach is a riddle. Who can open the port is an IP address on one form, a free text field on the other, and wrong for an agent on both.
  • The end is silent. Nobody says what stops when the window closes.

3.2 Sidebar

One view. Header "New service ▾" in text and "…". Search under it. Two collapsible groups with "n of m running", always in this order: SSH tunnels, File servers. An empty group is not shown. Groups follow what people compare (tunnels with tunnels); one flat list by name would mix rows that have nothing in common, and grouping by state would move a row away from under the pointer when it starts.

The New menu asks "what do you want to do". Each entry opens the editor tab with its type set.

The words for tunnels come from src/utils/tunnelTypeHelp.ts (hover and screen-reader help included). File servers get a sibling, shareTypeHelp.ts, with the same shape (label, technical name, summary, three lines). Without an SSH connection the first three entries stay enabled and the editor offers "Add an SSH connection".

3.3 List row

  • Line 1: state dot (name of the state as tooltip and accessible name), name, one state word when it needs attention, the run button. On hover, focus and selection: Activity, Edit, "…".
  • Line 2: the description, when the user wrote one.
  • Line 3, only while running: the address in the form the user can paste, with Copy: localhost:5432, http://192.168.1.20:8080, socks5://localhost:1080, localhost:9000 on shop-web for a remote tunnel (with the machine, because it opens there; only the address is copied). A wide bind shows the machine's network address, never 0.0.0.0. On an agent the agent's host. Question 1 asks for this exception to "names, not settings" (#5757).
  • Or one problem line in its place: the error, "Reconnecting, try 3 of 10", "Waiting for agent build-box", "Its SSH connection was deleted" with the one action that helps.
  • Tooltip: what the type does (first help line), the path, where it runs, start options, traffic. Same order for both kinds.

3.6 Activity, errors and retry

Activity is one view for both: state and since when, Start/Stop/Restart, the address with Copy and a "how to use it" line per type, four counters, then the log. The log has events for both kinds (started and by what, signed in, port open, connection lost, each retry, stopped and by whom) and, for file servers, today's access log with its filter, copy and clear, its transfers and top lists. Events are a bounded in-memory ring in the manager (200 per service). Nothing new is written to disk. An agent-hosted service shows the events the desktop saw.

Reconnect keeps today's policy (10 tries, 1 s doubling to 30 s). "Target refused" needs the forwarder to count refused targets, which it does not report today; it is part of slice 10 and can be dropped without harm to the rest.

Address rule: what the row shows is reachable from where the user sits, or the row says from where ("on agent build-box only", with the two fixes of today: let others reach it, or a hop to this computer).

3.8 Where it runs

"Run on" is this computer or an agent, in the same place for every type, stored with the service. For an agent the form asks the agent for its addresses (a small optional RPC); an older agent gets a text field. The folder on an agent is typed, as today. Changing it while the service runs stops it there first, after a question. Chaining stays a tunnel feature and is offered from "Who can open it".

3.9 Share via

The file browser keeps its entries, renamed to the New menu's words ("Share this folder in a browser…", "…by FTP…", "…by TFTP…"). A small dialog asks who and what, shows the address and starts it. By default it is temporary: it appears in Services with "Until termiHub closes" and is forgotten then, which ends the pile of "Quick Share (HTTP)" entries; "Keep" turns it into a normal one.

5. What else belongs here #

Thing Recommendation Reason
HTTP monitor Out It watches something; it opens no port and has no address. It lives with ping and port scan in Network tools.
X server Out One shared helper for SSH sessions, nothing to configure per item. Stays in Settings and Open connections.
VNC / RDP SSH tunnel Out Part of one connection, starts and ends with its tab, has no address to use elsewhere. Listing it would offer a Stop that breaks the session.
Agent port forwards for VNC/RDP Out Same as above, internal.
Port Forwarding in the connection editor In, as a view Same entries. Keeps its place (found while editing the host), uses the same rows, words and editor.
"Share via" in the file browser In, as an entry point Creates a file server; gets the dialog of 3.9.
SSH agent forwarding, X11 forwarding Out Options of a session.
Open connections Stays It answers "what is open" across everything. Its two sections become one, "Services".
Plugin-provided servers Out, later No plugin API for it. The view-model of slice 3 leaves room.

Risks

  • Behavior change hidden in a move. The shared row and shell are built next to the old ones and the old tests keep running against them before the old code goes.
  • Agent versions. Only the address list needs a new RPC; without it the form falls back to text. Events come from the desktop side.
  • Not reachable vs. stopped. Only the agent can tell. After a reconnect its service.status / tunnel.status decides.
  • Quit on agents. Today's stop at quit is kept unless question 2 changes it.

8. Open questions for the maintainer #

Three, all answered on 2026-11-25: the maintainer followed each recommendation. Everything else above is decided here and can be changed in the review of this concept.

  1. May a running row show its address with a Copy button? It is an exception to "users are looking for names, not the settings" (#5757). Recommendation: yes, only while it runs. Then the address is the result, the thing the user needs next, not a setting; stopped rows show names only. Otherwise the address moves to the tooltip and the menu, and Copy costs two clicks.
  2. Should termiHub ask before quitting when services run? Today it stops them silently, on agents too. Recommendation: ask only when one has connections open right now, in the existing quit dialog ("3 services stop, 2 connections are open"); otherwise quit at once. On Windows and Linux the last window closing counts as quit. Agent-hosted services keep stopping at quit, as today.
  3. May the defaults for new file servers become safer? Today a new server and every "Share via" lets anyone who reaches it upload, and the warning covers only 0.0.0.0. Recommendation: yes. New file servers start with "Only download"; "Share via" asks who and what and is temporary; a warning shows whenever other machines can reach it. Saved servers keep their settings.
