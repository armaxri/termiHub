Elevated SFTP Editing — Editor states

1 · Writable file (baseline)

Owner write bit set, or no permission info available → editor behaves exactly as today. No new chrome.
Remote /home/pi/notes.txt
1Shopping list 2- coffee 3

2 · Read-only detected at open time

Permission probe at load finds the file is not writable. A warning badge sits in the toolbar, an info banner explains why, and Save is replaced by an Edit with sudo affordance (only when a shell is available on the connection).
Remote Read-only A /etc/nginx/nginx.conf
You don't have write access to this file (-rw-r--r--). Saving directly will fail. to save through privilege elevation. C
1user www-data; 2worker_processes auto; 3pid /run/nginx.pid;
  • A Read-only badge (lucide Lock) in warning color, with the parsed permission string as a tooltip.
  • B Edit with sudo button (lucide ShieldCheck) replaces Save when the file is read-only and the connection has shell access. Hidden for SFTP-only connections (see banner in state 5).
  • C Dismissible info banner: explains the cause and offers the same elevate action inline.

3 · Elevated edit mode (sudo authorized)

After the user authorizes elevation (see sudo-prompt mockup), the buffer becomes editable. The toolbar shows a persistent sudo marker so it is always obvious the next save runs as root.
Remote sudo D /etc/nginx/nginx.conf
1user www-data; 2worker_processes 4; 3pid /run/nginx.pid;
  • D Persistent sudo marker (accent color) — visible for the whole elevated session so the privileged context is never hidden.
  • E Save button label becomes Save with sudo to confirm the write path before the user commits.

4 · Elevated save failed (retry)

Wrong password, sudo not permitted, or the remote command failed. The existing save-error banner (#969) carries the elevated context and lets the user re-enter the password or fall back.
Remote sudo /etc/nginx/nginx.conf
Elevated save failed — sudo: incorrect password. Your changes are kept; retry to re-enter the password. F
1user www-data; 2worker_processes 4; 3pid /run/nginx.pid;
  • F Reuses the #969 dismissible save-error banner; the buffer and unsaved changes are preserved. Clicking Save re-opens the sudo prompt.

5 · Read-only, no elevation available (SFTP-only)

The connection is a pure SFTP connection (no shell channel to run sudo). The read-only state is still surfaced, but no elevate affordance is offered — only an honest explanation and a Download / Save-As fallback.
Remote Read-only /etc/hosts
You don't have write access (-rw-r--r--). This is an SFTP-only connection, so sudo elevation isn't available. G
1127.0.0.1 localhost 2::1 localhost
  • G No Edit with sudo button — instead a Save a copy… fallback writes to a writable path or downloads locally. Save stays disabled.
