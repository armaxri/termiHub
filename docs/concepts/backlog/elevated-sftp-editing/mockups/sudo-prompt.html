Elevated SFTP Editing — Sudo password prompt

Layout-altitude mockup · docs/concepts/backlog/elevated-sftp-editing/mockups/sudo-prompt.html

1 · Initial prompt

Shown when the user triggers Edit with sudo or Save with sudo and no cached password is available.
Authorize elevated save
termiHub will run sudo on pi@raspberrypi to write /etc/nginx/nginx.conf as root. A
sudo password for pi
  • A Always names the exact command target (host, user, file) so the user knows what they are authorizing.
  • B Default: cache in the in-memory session only. If the credential store is unlocked, an optional second choice can persist it (state 3).

2 · Incorrect password

Sudo rejected the password. The field is highlighted; the dialog stays open for a retry (matches sudo's three-attempt behavior).
Authorize elevated save
termiHub will run sudo on pi@raspberrypi to write /etc/nginx/nginx.conf as root.
sudo password for pi
Sorry, try again (attempt 2 of 3). C
  • C Re-prompt loop. After the third failure the dialog closes and the editor shows the elevated-save-failed banner (editor-states state 4). A wrong cached password is discarded automatically.

3 · Persist offered (credential store unlocked)

When the master-password credential store is unlocked, the user may opt to persist the sudo password under a dedicated credential key so it survives app restarts.
Authorize elevated save
termiHub will run sudo on pi@raspberrypi to write /etc/nginx/nginx.conf as root.
sudo password for pi
Remember for this session only
Save in credential store (until removed) D
Credential store: Unlocked
  • D Persisted under a new CredentialType::SudoPassword key, keyed by connection id. Hidden / disabled when the credential store is Locked or Unavailable — only the session option remains.
