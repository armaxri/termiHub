1 · Update Prompt dialog

Opened from the sidebar "Update available" badge. Shows installed vs. available versions. If other hosts are connected, a warning A lists them and the primary action becomes "Notify Others & Update". With no other hosts, the warning is omitted and the action is a plain "Update".

With other hosts connected (Approach 2 guard)

Update agent on prod-server-1
Installed v0.2.1
Available v0.3.0
2 other host(s) are connected to this agent:
  • staging-pc — connected 43 min ago
  • macbook-anne — connected 2 h ago
They will receive a disconnect notice and reconnect automatically.

No other hosts — direct update

Update agent on dev-box
Installed v0.2.1
Available v0.3.0
No other hosts are connected. The update applies immediately.
  • A Other-hosts warning — amber callout listing connected clients from agent.list_connections.

2 · "Being updated by another host" notice (Approach 3)

Shown on every other connected host when one host initiates a coordinated update. Sessions pause; a progress bar B tracks the restart; the host reconnects automatically when the new agent is up.
Agent on prod-server-1 is being updated
Update requested by another host. Sessions will be paused briefly and reconnect automatically.
Waiting for update… reconnecting in ~10s
  • B Restart progress — --accent-color fill, driven by the agent.update_pending estimate.

3 · Deferred-update banner (Approach 4)

Inline banner shown while an update is pending but sessions are still active. The update applies automatically on the last disconnect; "Apply Now" forces it immediately.
Agent update pending on prod-server-1 — applying on last disconnect.

4 · Self-update toast (Approach 1 — agent-initiated)

Transient toast (lower-right corner) raised when the agent's own GitHub poll finds a newer release. Offers to update now or defer.
termihub-agent v0.3.0 is available on prod-server-1
Installed v0.2.1 · this host v0.3.0
