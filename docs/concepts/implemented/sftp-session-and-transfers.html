Overview #

The SFTP file browser has two structural defects called out by the audit (gaps L1, L2, D1, D3). This concept designs the fix for both, concept-first, before any code is written.

Orphaned, invisible, unkillable sessions. The Rust SftpManager already holds N sessions in a HashMap<String, Arc<Mutex<SftpSession>>>, but the frontend tracks only a single slot — one sftpSessionId plus one sftpConnectedHost string. When the owning tab closes, or the user switches to another host, the old UUID is silently overwritten with no sftp_close. The dedicated SSH+SFTP connection stays open on the server forever, and because the Open Connections panel derives its "SFTP" row purely from the single sftpConnectedHost string, those orphaned sessions never appear and cannot be killed — directly contradicting the panel's mandate as the canonical place to kill every connection. Quitting the app leaves them dangling too: no shutdown hook closes SFTP.

Transfers freeze the whole browser and can't be cancelled. sftp_download / sftp_upload read the entire file into a Vec<u8> in RAM and hold the per-session Mutex for the whole copy. A multi-GB transfer consumes RAM equal to the file size and blocks every other list / navigate on that session — with no spinner, because the shared sftpLoading flag is never even set for transfers. There is no progress event, no cancel token, and (per gap D2) no error feedback. A user who starts a large or wrong transfer has no way to see it, no way to stop it, and no idea whether the frozen browser is working or hung.

Goals

  • L1 — key SFTP sessions in a frontend map (by session-id), close the session on owning-tab close and on host-switch, and surface every live session (one Open Connections row per HashMap entry) with a per-session Kill.
  • L2 — add SftpManager::close_all() and wire it to the Tauri window Destroyed / app-exit handler alongside the existing manager cleanups.
  • D1 — a cancellable, chunked transfer subsystem that runs off the shared session Mutex (dedicated channel), so browsing stays live during a transfer, with a per-transfer id + cancel command.
  • D3 — emit chunked progress events and render them: a progress indicator with a Cancel control, and each active transfer visible in Open Connections.

Non-Goals

  • The connect-failure Retry (S1), dead-session Reconnect (S2), the sftpStatus enum (A1), the overlapping-list race (R1), and the transfer-error toast wiring (D2) are separate audit gaps — related but out of this issue's L1/L2/D1/D3 scope. They get their own follow-ups.
  • No resumable / restartable transfers, no transfer queue reordering UI in this pass.
  • No change to the agent-side (remote) file browser — this concept targets the desktop SftpManager path (src-tauri/src/files/sftp.rs).

UI Interface #

Three user-facing surfaces change. (1) The Open Connections panel gains a real per-session SFTP section — one row per live backend session, each with a Kill — plus a Transfers section for in-flight copies, each with a Cancel. (2) The file browser toolbar/footer gains a transfer progress indicator with a Cancel control. (3) Nothing new is visible for close-all-on-quit — it just runs. The mockups below are authoritative for layout; they reuse the real OpenConnectionsModal section/row structure (title + count + kill-all; per-row badge + Kill).

General Handling #

Session lifecycle workflows (L1 / L2)

  • Open. The auto-connect effect opens a session for the active tab's host; sftp_open returns a UUID. The frontend records it in a keyed map Record<sessionId, SftpSessionMeta> (meta = host label + owning tab id), not a single slot.
  • Owning-tab close. On closeTab, if the closing tab owns any SFTP session(s), the store calls sftpClose(sessionId) for each and removes them from the map. This is the L1 leak fix: the SSH+SFTP connection is torn down instead of orphaned.
  • Host switch. When the browser re-targets a different host, the previous session is not silently overwritten — it is explicitly closed (if the old tab is gone) or left registered (if the old tab is still open and may return to it). Keying by session-id makes "which sessions still have a live owner" answerable, which the single slot could not.
  • Orphan safety net. Should a session ever end up with no owning tab (edge cases, races), it still appears in Open Connections with a warning badge and a Kill — so it is never invisible. This is the belt to L1's suspenders.
  • App quit. On window Destroyed / app exit, the Rust handler calls SftpManager::close_all() alongside the existing tunnel / embedded-server / X-server / HTTP-monitor cleanups already wired there (L2). No orphan is left on the server.

Transfer workflows (D1 / D3)

  • Start. Download/upload registers a transfer in a Rust TransferRegistry keyed by a fresh transfer_id, returns that id immediately, and spawns the copy on a dedicated SFTP channel cloned from the session's SSH connection — not under the shared session Mutex. Browsing on the same session therefore stays responsive.
  • Chunked progress. The copy loops over fixed-size chunks (e.g. 256 KiB), writing each and emitting a throttled transfer-progress event ({ transferId, transferred, total, phase }). The UI renders a percentage + bar in both the file-browser footer and the Open Connections Transfers row.
  • Cancel mid-transfer. Each chunk checks a CancellationToken. sftp_cancel_transfer(transferId) trips the token; the loop stops at the next chunk boundary, closes the dedicated channel, removes the partial destination file (download) or leaves a clearly-partial remote file flagged for the user (upload), emits a terminal cancelled progress event, and drops the registry entry.
  • Concurrent transfers. Because each transfer uses its own channel and its own registry entry, multiple transfers on the same or different sessions run in parallel and each reports independently. The Transfers section aggregates them; the status bar shows the count + rolled-up percentage.
  • Completion & error. On success the registry entry is dropped and a terminal done event fires (→ success toast, D2 follow-up). On error a terminal error event fires with the message (→ error toast, D2 follow-up). Either way the transfer row clears.

Edge cases

  • Session killed while a transfer runs. Killing an SFTP session in Open Connections first cancels any transfers owned by it, then closes the session — so no transfer keeps a dead session's channel alive.
  • App quit with an active transfer. close_all() trips every transfer's cancel token before closing sessions, so no half-written file keeps a channel open during teardown.
  • Unknown / stale transfer id. sftp_cancel_transfer on an already-finished id is a no-op (the registry entry is gone) rather than an error.
  • Zero-byte / tiny files. The chunk loop still emits at least a 0% start and a terminal done so the UI is consistent.

Design Decisions #

Decision 1 — key sessions by session-id, not by host

Recommendation: key by session-id (UUID). The backend SftpManager already keys its HashMap by UUID, and sftp_close / get_session take a session id. Keying the frontend map the same way makes the two sides bijective, so Open Connections can render exactly one row per live backend entry — the L1 requirement that every session be visible and killable.

Keying by host would collapse two sessions to the same host into one slot (exactly today's single-slot bug in a thinner disguise) and would make an orphaned previous-host session — whose whole problem is that its host is not the current one — unrepresentable. Host stays as display metadata (SftpSessionMeta.hostLabel) on the id-keyed entry, plus the owning-tab id so close-on-tab-close and orphan detection work. Net: Record<sessionId, { hostLabel, owningTabId }>.

Decision 2 — transfer chunk/cancel protocol

Progress-event shape. A single Tauri event channel, transfer-progress, carries the whole transfer lifecycle so the UI has one subscription:

Field Type Meaning
transferId string UUID minted at registration; the cancel key.
sessionId string Owning SFTP session (for the Open Connections row + kill-cascade).
direction "download" | "upload" Drives the icon / verb.
fileName string Display label.
transferred / total number (bytes) total = 0 means indeterminate (stat unavailable); show a spinner.
phase "transferring" | "done" | "cancelled" | "error" Terminal phases clear the row; error carries message.

Cancel command. One new command sftp_cancel_transfer(transferId: string) trips the transfer's CancellationToken in the TransferRegistry; unknown/finished ids are a no-op. sftp_download / sftp_upload change to return the transferId synchronously (registration) and run the copy in the background, rather than blocking until the whole file is done. Progress is throttled (emit at most ~10 Hz or every N chunks) to avoid flooding the event bus. Chunk size starts at 256 KiB (tunable) — large enough to keep SFTP round-trips amortised, small enough that cancel latency stays sub-second.

Preliminary Implementation Details #

Grounded in the current code (src-tauri/src/files/sftp.rs, src-tauri/src/commands/files.rs, src-tauri/src/lib.rs, src/store/appStore.ts, src/services/api.ts, src/components/OpenConnections/OpenConnectionsModal.tsx). Staged S1 = L1 + L2 (session tracking + close-all), then S2 = D1 + D3 (cancellable chunked transfers + progress). S1 lands first because a keyed session map and a live kill surface are prerequisites for surfacing transfers per-session in S2.

Notes

  • The dedicated-channel approach reuses the existing SftpSession::new pattern (channel_open_session → request_subsystem("sftp") → RusshSftp::new, sftp.rs L47–61) — transfers open their own channel from the same authenticated SshSession instead of sharing the browse channel's mutex.
  • Libraries first: use tokio_util::sync::CancellationToken for cancel and Tauri's built-in Emitter for progress (already imported in lib.rs) rather than hand-rolled channels. russh-sftp's File already implements chunked AsyncRead/AsyncWrite, so the loop is a read/write chunk pair, not custom framing.
  • Tests: unit-test close_all (poison-safe drain) and the keyed-map close-on-tab-close store logic; a Docker SFTP integration test for a cancel-mid-transfer (partial file removed) and a concurrent-transfer-while-browsing liveness check.
