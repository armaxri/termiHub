Overview #

Opening a connection today shows a lone spinner over the terminal with “Connecting… · Elapsed 4s · times out in 86s · Abort / Cancel”. The maintainer’s hands-on verdict: the spinner looks stuck, and the surface looks ugly. Every connection type (local, SSH, telnet, serial, Docker, WSL, agent, RDP/VNC) also gets a slightly different variant of it.

This concept replaces all of them with one shared connect surface that shows what is happening (target, type, stage, last status line), how long it may still take (a timeout-tracking ring or bar), and offers one obvious primary action.

Goals

  • One component for every connection type, composed from src/components/ui, tokens only.
  • Visible stages where known (resolve → connect → authenticate → session); a live status line.
  • Elapsed / timeout as a progress ring or bar, not as prose.
  • Motion that can never look frozen, and a reduced-motion mode that still reads as “alive”.
  • Abort as the primary action; clear Abort / Close semantics (no two buttons that look alike).

Non-Goals

  • Changing connect timeouts, retry budgets, or auth flows (host-key / password prompts keep their dialogs).
  • The agent deploy wizard (AgentSetupDialog) — it can reuse the stepper later.

Why the spinner reads as frozen

  1. It is a lone, featureless glyph. A 32px Loader2 arc, uniform stroke, spinning at 1 rev/s, over a blurred terminal. Nothing else on screen moves except one number that changes once per second, so there is nothing to confirm progress.
  2. Under reduced motion it is frozen by design. The shared spinner carries .motion-essential-spinner, which renders it static under prefers-reduced-motion (#4039). The only liveness cue left is the once-per-second text. (The maintainer’s Mac has Reduce Motion off, so this is not the observed case, but it is the same surface.)
  3. The rotation can stall with the main thread. The spin is CSS (th-spin), not JS, but it rotates an inline <svg> inside a backdrop-filter layer laid over the xterm canvas. WebKit does not reliably composite that, so the spin runs on the main thread, and a connect burst (IPC, store fan-out, xterm writes) makes it stutter or pause. The elapsed text comes from a 1s setInterval, which WKWebView throttles when the window is occluded or in the background.

Fix built into both options: liveness comes from a compositor-only transform on an HTML element (the comet / the shimmer), and the timeout fill is a CSS animation started with a negative delay equal to the elapsed time, so it advances on the animation clock and never waits on a JS timer. Under reduced motion both stop; the fill steps once per second instead, and a status line that changes with each stage carries the progress signal. Whether the WebKit stall (item 3) is the real cause will be checked on the device in phase 2, with an A/B build.

UI Interface — Option A vs Option B #

Both options are shown for three connection types (Telnet, SSH through a jump host, an agent-hosted shell waiting for its agent) and for the three resting outcomes (failed, timed out, aborted), in Dark and in Light. A frozen screenshot cannot show the motion; open this file in a browser to see it.

Option A — stage stepper + progress ring + live status line (recommended)

Centred over the terminal. The ring fills toward the timeout, and a comet orbits it so the surface is visibly alive. The type glyph sits in the centre. Below: target, type chips, the stage stepper (the active stage pulses), the latest status / log line, and “elapsed · times out in”. One action while busy (Abort); Retry / Close tab when resting. This is exactly what the React prototype renders.

Option B — compact card + progress bar + expandable log

A small floating card (like a toast, centred). The header has the type tile with a “connecting” dot, a title, a sub-line (“step 2 of 3 — Connect”) and the elapsed time. General Handling #

Actions: one meaning per button

  • Abort (busy, primary): stop the connect and land on the aborted resting state. The tab stays open. Today’s separate Cancel (= close the tab) is dropped from the busy state, because the tab’s own × already closes it and two adjacent buttons with different meanings were the confusion.
  • Retry now (waiting for agent / backing off): skip the wait.
  • Retry (resting, primary, auto-focused on the active tab) and Close tab (ghost).

Stages per connection type

Type Stages shown Source
SSH (+ jump hosts) Resolve · Connect · Host key · Authenticate · Shell (a jump host adds “via bastion”; its own hops reuse the path-probe events) new connect-progress event (phase 2)
Telnet Resolve · Connect · Session new event
Serial Open port · Configure new event
Agent-hosted session Agent · Start session (then the inner type’s stages) existing terminalWaitingForAgent + new event
RDP / VNC Connect · Authenticate · Desktop existing GraphicalState
Local / WSL / Docker / SFTP none: ring + status line only (usually under 300 ms, see below) —

Timing rules

  • Show the surface only after 250 ms, so instant local spawns never flash it.
  • After 20 s the status line adds “Taking longer than usual — the host may be slow or unreachable” (today’s hint, kept).
  • Retrying: the ring has no fill (the total is unknown); the time line reads “Attempt 2 of 5 · next try in 3s”.
  • The failure body keeps today’s contextual hint and copyable fix command (connectionErrorHint).

Accessibility & motion

  • The surface composes ContentOverlay: aria-busy, a polite live region for busy states, assertive for failures, focus to the primary action on the active tab.
  • The stepper is an <ol> with aria-current="step".
  • Reduced motion: no comet, no pulse, no shimmer. The fill steps once per second, and the status line and stepper carry progress.

Preliminary Implementation Details #

File Change
src/components/ui/ConnectProgress.tsx + ui.css Prototype exists (phase 1, not wired): ring, stepper, status line, time line, resting badges, composed on ContentOverlay. Unit-tested; the visual lane renders a gallery (tests/visual/connectProgress.spec.ts).
TerminalConnectionOverlay.tsx Phase 2: render ConnectProgress for all five states; drop the busy-state Cancel; keep the hints and copy-command blocks as the error body.
RemoteDesktopOverlay.tsx, FileBrowserTab.tsx Phase 2: same component; map GraphicalState to stages.
core / src-tauri Phase 2b: a typed connect-progress event (stage id + optional status) from the SSH, telnet and serial connect paths into the session-lifecycle region. Until then, stages are derived on the frontend (agent wait → connect → session).
